
## PDF 缺页/丢图 + 分割线 + git 回退（第六轮需求，接续昨天中断）

**PDF 缺页/丢图的根因**：pdfjs-dist 6.5.438 的 JPEG2000 / JBIG2 解码与 ICC 色彩管理
走 WASM，但 getDocument 没配 `wasmUrl` → 这些解码器静默不可用。扫描版 PDF（每页
一张 JPX 图）整页空白像「缺页」，普通 PDF 丢插图 —— 两个症状同一个根因。
修复：copy `pdfjs-dist/wasm` 与 `iccs` 到 `public/pdfjs/`，getDocument 加
`wasmUrl: '/pdfjs/wasm/'`、`iccUrl: '/pdfjs/iccs/'`（useWorkerFetch 因三个 URL 齐全自动启用）。
另加两道保险：单页渲染失败显示「第 N 页渲染失败 + 重试」；超大页面在高缩放下
自动压 dpr（Chromium 画布上限 16384px / 2^24 像素）。

**分割线**：markdown-syntax 加 `hr` block（`---`/`***`/`___`，frontmatter 的 `---` 除外），
实时预览整行换 HrWidget，阅读模式 marked 原生支持。

**git 回退**：`revertToCommit(vault, oid, message, author)`——git.walk 对比 HEAD 树与
目标树，删除多余文件、覆盖改动文件，commitAll 生成新提交（不重写历史，push 免 force）。
坑：`git.readCommit` 只认 oid 不认 'HEAD'，要先 `git.resolveRef`。sync store 加
`revertToCommit` action（先自动提交当前改动）；SyncSection 历史列表每条加「回退」
（两步确认，最新一条禁用）。2 条单测（MemoryVaultFS 内存仓库）。

验证：CDP 实测 PDF 正常渲染无 wasm 报错、`---`/`***` 在实时预览与阅读模式都成 hr、
frontmatter 的 `---` 不受影响。356 条测试全绿，安装包重打（13:45，5.88 MiB 含 wasm）。

  356 测试全绿，安装包重打（19:09，5.89 MiB）。

## 独立笔记显示名 = 文件名（第九轮反馈）

用户发现独立笔记在 app 里显示的名字和实际文件名不一样。根因：显示名取正文
第一个 `# 标题`（noteTitle），文件名是创建/重命名时的 slug —— 在编辑器里改标题
后两边就漂移（例：文件 `未命名笔记.md`，正文 `# one`，app 显示「one」）。
修复：`toNote` 的 title 直接取 slug（文件名去 .md），standalone.save 不再用
extractTitle 回填标题（正文标题只是内容）。想改名走「点击标题重命名」，
repo.rename 会同时改文件名和 `# 标题`，两边永远同步。
顺手清掉了之前测试误粘贴进用户笔记的 wiki 行（拼坏了 `# 未命名笔记` 标题行）。
实测 headerTitle = 文件名。356 测试全绿，安装包重打（22:22）。
